# 01 · 初始化项目

🎯 **这一节验证什么：** `brickkit init` 生成的骨架长什么样，配置改坏了怎么退回去。

前置：`./试用指南/准备.sh --reset`（空试验场，[00](00-准备.md) 里那三个命名状态之一），
并且当前终端已经 `export PATH=".../试用指南/bin:$PATH"`。

---

## 1.1 初始化

### ▶️ 操作

```bash
cd 试用指南/playground
brickkit init demo-shop
```

### ✅ 预期

```
✅ 项目已初始化：demo-shop
   📁 brickkit.yaml        项目配置
   📁 components/          组件源码（已配为本地安装源 local-dev）
   📁 .brickkit/           CLI 工作目录
   📁 .brickkit/backup/    配置备份

下一步：
  brickkit add --local               把 components/ 下的组件全加进来
  brickkit add people/basic@1.0.0    从安装源添加组件
  brickkit up                        一键启动
```

生成的 `brickkit.yaml`：

```yaml
# brickkit.yaml - BrickKit 项目配置
# 由 brickkit init 生成，由用户编辑，由 CLI 读取
project: demo-shop

deploy:
  target: docker          # docker | k8s

# 安装源：按声明顺序依次尝试，前一个找不到就试下一个（003 §6.5）
sources:
  - id: local-dev
    type: local
    path: ./components      # brickkit init 已经建好这个目录
  # 组件市场按需取消注释并填上地址：
  # - id: brickkit-market
  #   type: market
  #   url: https://market.example.com/api/v1

components: []
resources: []
```

### 顺手看一眼项目名规则

```bash
brickkit init 试用
```

会明确报错——项目名要用作 K8s 命名空间与 Docker 网络名，只能是小写字母、数字、中划线：

```
❌ 错误：项目名称不合法
   项目名称：试用
   原因：包含非法字符（仅允许小写字母、数字与中划线）
```

## 1.2 目录结构

### ▶️ 操作

```bash
ls -a
cat .gitignore
```

### ✅ 预期

```
.brickkit/          CLI 工作目录
.gitignore          init 自动写入（已存在则只补缺失的规则，不覆盖）
brickkit.yaml       你要编辑的唯一文件
components/         组件源码（00 的脚本放进来的）
```

`.brickkit/` 下各目录的分工：

| 目录 | 内容 | 进 Git 吗 |
| --- | --- | --- |
| `backup/` | `brickkit.yaml` 的初始备份与上次备份 | ❌ |
| `manifests/` | 拉下来的 `component.yaml` 缓存 | 可选（默认进） |
| `artifacts/` | 组件产物（proto、openapi.json 等） | 可选（默认进） |
| `generated/` | 生成的部署文件 | ❌ |
| `credentials` | 市场登录 Token | ❌ |

`.gitignore` 里 `.brickkit/generated/`、`.env`、`credentials` 一定是被忽略的——**生成物与密码不进版本库**。

## 1.3 改坏了怎么退回去

CLI 存两份备份，恢复到哪一份由参数决定：

| 命令 | 恢复到 | 什么时候生成的 |
| --- | --- | --- |
| `brickkit reset` | `brickkit init` 刚生成时的样子 | `init` 时，一次 |
| `brickkit reset --last` | 上一次 `add` / `remove` **之前** | 每次 `add` / `remove` 之前 |

### ▶️ 操作

把配置写坏，再退回去：

```bash
echo "这是一行手滑写进去的垃圾" >> brickkit.yaml
brickkit order                  # 会报解析失败
brickkit reset                  # 回到 init 刚生成的样子
cat brickkit.yaml
```

### ✅ 预期

```
🔄 已恢复 brickkit.yaml 到初始状态
   备份位置：.brickkit/backup/brickkit.yaml.initial
   ...

⚠️ 注意：恢复后需要重新执行 brickkit up 使变更生效
```

那行垃圾没了，`brickkit order` 又能跑了（只是现在还没有组件）。

### 顺手看一眼：现在还没有 `.last`

```bash
brickkit reset --last
```

```
❌ 错误：备份文件不存在
   备份文件：.brickkit/backup/brickkit.yaml.last
   原因：.last 在每次 brickkit add / brickkit remove 前自动生成，当前还没有生成过
   建议：
   1. 先执行一次 brickkit add / brickkit remove，之后即可用 brickkit reset --last 回退
   2. 或执行 brickkit reset 恢复到初始状态
```

**这不是报错，是这个项目现在的真实状态**——`.last` 要等你第一次 `add` 或 `remove`
之后才存在。[02](02-添加与移除组件.md) 里装过组件之后，`reset --last` 就能一步一步往回退了。

> 两份备份的分工：`.initial` 是"推倒重来"，`.last` 是"撤销刚才那一步"。
> 都只动 `brickkit.yaml` 本身，不碰 `.brickkit/` 下的缓存，也不碰 `components/`
> 下的源码——**要连试验场一起重来，用 `./试用指南/准备.sh --reset`**。
