# 01 · 初始化项目

🎯 **这一节验证什么：** `brickkit init` 生成的骨架长什么样，配置改坏了怎么退回去。

前置：`./试用指南/准备.sh --reset`（空试验场，[00](00-准备.md) 里那三个命名状态之一），
并且当前终端已经 `export PATH=".../试用指南/bin:$PATH"`。

---

## 1.1 初始化

### ▶️ 操作

```bash
cd 试用指南/playground
brickkit init demo-shop
```

### ✅ 预期

```
✅ 项目已初始化：demo-shop
   📁 brickkit.yaml        项目配置
   📁 components/          组件源码（已配为本地安装源 local-dev）
   📁 .brickkit/           CLI 工作目录

下一步：
  brickkit add --local               把 components/ 下的组件全加进来
  brickkit add people/basic@1.0.0    从安装源添加组件
  brickkit up                        一键启动
```

生成的 `brickkit.yaml`：

```yaml
# brickkit.yaml - BrickKit 项目配置
# 由 brickkit init 生成，由用户编辑，由 CLI 读取
project: demo-shop

deploy:
  target: docker          # docker | k8s

# 安装源：按声明顺序依次尝试，前一个找不到就试下一个（003 §6.5）
sources:
  - id: local-dev
    type: local
    path: ./components      # brickkit init 已经建好这个目录
  # 组件市场按需取消注释并填上地址：
  # - id: brickkit-market
  #   type: market
  #   url: https://market.example.com/api/v1

components: []
resources: []
```

### 顺手看一眼项目名规则

```bash
brickkit init 试用
```

会明确报错——项目名要用作 K8s 命名空间与 Docker 网络名，只能是小写字母、数字、中划线：

```
❌ 错误：项目名称不合法
   项目名称：试用
   原因：包含非法字符（仅允许小写字母、数字与中划线）
```

## 1.2 目录结构

### ▶️ 操作

```bash
ls -a
cat .gitignore
```

### ✅ 预期

```
.brickkit/          CLI 工作目录
.gitignore          init 自动写入（已存在则只补缺失的规则，不覆盖）
brickkit.yaml       你要编辑的唯一文件
components/         组件源码（00 的脚本放进来的）
```

`.brickkit/` 下各目录的分工：

| 目录 | 内容 | 进 Git 吗 |
| --- | --- | --- |
| `backup/` | `brickkit.yaml` 的初始备份与上次备份 | ❌ |
| `manifests/` | 拉下来的 `component.yaml` 缓存 | 可选（默认进） |
| `artifacts/` | 组件产物（proto、openapi.json 等） | 可选（默认进） |
| `generated/` | 生成的部署文件 | ❌ |
| `credentials` | 市场登录 Token | ❌ |

`.gitignore` 里 `.brickkit/generated/`、`.env`、`credentials` 一定是被忽略的——**生成物与密码不进版本库**。

## 1.3 改坏了怎么退回去

**CLI 不做备份，也没有 `brickkit reset`。** `brickkit.yaml` 是要提交进 Git 的文件
（上面那份 `.gitignore` 里没有它，是刻意的），退回去用 Git 就行——
而且比自建备份强：能看差异、能挑着退、能退很多步、换台机器也在。

所以新项目的第一件事，是把它提交上去：

### ▶️ 操作

```bash
git init -q
git add brickkit.yaml .gitignore
git commit -qm "init: brickkit 项目骨架"
```

然后把配置写坏，再退回去：

```bash
echo "这是一行手滑写进去的垃圾" >> brickkit.yaml
brickkit order                  # 会报解析失败

git diff brickkit.yaml          # 看清楚到底改了什么
git checkout brickkit.yaml      # 退回上次提交
brickkit order                  # 又能跑了（只是现在还没有组件）
```

### ✅ 预期

`git diff` 里能看到那一行多出来的垃圾：

```
+这是一行手滑写进去的垃圾
```

`git checkout` 之后那行没了，`brickkit order` 恢复正常。

> **和 `准备.sh --reset` 的分工**：`git checkout` 只动 `brickkit.yaml` 本身，
> 不碰 `.brickkit/` 下的缓存，也不碰 `components/` 下的源码。
> **要连试验场一起重来，用 `./试用指南/准备.sh --reset`。**

> **改了一大片、只想退其中一处？** `git checkout -p brickkit.yaml` 会逐块问你留不留。
> 这正是当初那套 `.initial` / `.last` 做不到、因而被删掉的事（003 §7.2）。


## ⏹️ 怎么停
