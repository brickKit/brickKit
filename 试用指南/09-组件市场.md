# 09 · 组件市场

🎯 **这一节验证什么：** 把市场后端跑起来，登录、发布一个组件、再从市场把它装回来。

前置：Docker 可用。这一节独立于 05–08，随时可以做。

---

## 9.1 起市场后端

市场是一套独立的服务：**市场服务 + PostgreSQL + RustFS（S3 兼容对象存储）**。

### ▶️ 操作

```bash
cd deploy/market
cp .env.example .env
vi .env                     # 至少填 POSTGRES_PASSWORD / RUSTFS_SECRET_KEY / ADMIN_PASSWORD
docker compose up -d
```

> **镜像要先有。** `.env` 里的 `MARKET_IMAGE=brickkit/market-server:dev` 是本地
> 标签，公开仓库没有这个镜像。第一次跑之前在仓库根目录构建一次：
>
> ```bash
> docker build -t brickkit/market-server:dev --build-arg VERSION=dev market-server/
> ```
>
> **端口被占的话改 `.env`。** 本机已经跑着别的 RustFS/MinIO 时会看到：
>
> ```
> Bind for 0.0.0.0:9001 failed: port is already allocated
> ```
>
> 改 `RUSTFS_CONSOLE_PORT`（管理界面）或 `MARKET_PORT` 即可。
> RustFS 的 S3 端口 9000 **不发布到宿主机**——市场通过内部网络访问它，不会冲突。

等它起来：

```bash
docker compose ps
curl http://localhost:8080/api/v1/health
```

### ✅ 预期

`health` 返回 200。三个容器都 healthy。

> **`.env` 必须和 `docker-compose.yaml` 同目录** —— docker compose 只读项目目录（默认就是 compose 文件所在目录）下的 `.env`。这一点和 BrickKit 项目不一样：那边 CLI 会显式传 `--project-directory`，把项目根的 `.env` 喂给 compose。

## 9.2 登录

### ▶️ 操作

```bash
cd <你的 BrickKit 项目目录>
brickkit login --market http://localhost:8080/api/v1 --username admin
```

会交互式问密码（不回显）。CI 里用：

```bash
echo "$PASSWORD" | brickkit login --market ... --username admin --password-stdin
```

### ✅ 预期

Token 存进 `.brickkit/credentials`（`.gitignore` 已忽略）。Token 过期后 CLI 会明确提示重新登录，而不是给一句看不懂的 401。

## 9.3 发布一个组件

### ▶️ 操作

```bash
cd 试用指南/playground/components/demo/hello
brickkit publish --market http://localhost:8080/api/v1 \
                 --changelog "第一次发布" \
                 --visibility public \
                 --source-type git \
                 --git-url https://example.com/demo/hello.git \
                 --no-pin-digest
```

`--path` 默认是当前目录（要有 `component.yaml`）。

> **两个参数是为本地试用加的，生产发布时都不该出现：**
>
> `--no-pin-digest` —— 平台默认会把镜像 tag 解析成 digest 再签名（P29），
> 而 `brickkit-demo/hello:1.0.0` 只在你本机、没推到任何 registry，解析必然失败：
>
> ```
> ❌ 错误：无法确定镜像的 digest，发布已中止
>    为什么要拦住：取不到 digest 通常意味着这个镜像消费方也拉不到——
>         与其在市场里留下一个装不上的版本，不如现在停下
> ```
>
> `--source-type git` —— 换成 `registry`（闭源）的话会被下面那条源头校验拦下：
> demo/hello 声明的产物类型是 `api-docs`，而闭源组件必须提供 `api-contract`。
> 这正是下表第二行，你可以自己换回 `registry` 看一眼。

### ✅ 预期

发布前市场会做**源头校验**，这几类会被直接拒绝：

| 拒绝原因 | 为什么 |
| --- | --- |
| `configSchema` 里用了平台保留变量（`COMPONENT_ID`、`DATABASE_*` 等） | 注入时会撞车。市场是第一道闸，CLI 是最后一道 |
| 闭源组件（`source-type: registry`）没提供 API 契约产物 | 别人拿不到契约就没法对接 |
| 同一个版本重复发布 | 版本是不可变的 |

## 9.4 从市场装回来

### ▶️ 操作

在一个新项目里，把市场配成安装源：

```yaml
sources:
  - id: brickkit-market
    type: market
    url: http://localhost:8080/api/v1
    # authToken: ${MARKET_TOKEN}    # 也可以不写：已 login 的话 CLI 用登录态
    enabled: true

  - id: local-dev
    type: local
    path: ./components
    enabled: true
```

```bash
brickkit add demo/hello@1.0.0
```

### ✅ 预期

多个源按**声明顺序**依次尝试。市场里没有就试下一个源；两个源都没有才报"组件未找到"，并列出**试过哪些源**。

被下架（blocked）的版本会给出"该版本已被市场下架"，而不是笼统的"认证失败，请登录"。

---

## ⏹️ 怎么停

```bash
cd deploy/market
docker compose down            # 停掉市场，数据保留在 ./data/
docker compose down -v         # 连数据一起删
```

登出（删掉本地 Token）：

```bash
rm .brickkit/credentials
```

---

> **起过市场之后 `go test ./...` 会失败**，报的是：
>
> ```
> pattern ./...: open deploy/market/data/postgres: permission denied
> ```
>
> 那些目录属主是容器内的用户（uid 10001 / postgres），而 Go 遍历 `./...` 时
> 不看 `.gitignore`。**这跟你的测试毫无关系**，别去查代码。清掉即可：
>
> ```bash
> cd deploy/market
> docker run --rm -v "$PWD/data:/data" busybox rm -rf /data/postgres /data/rustfs
> ```
