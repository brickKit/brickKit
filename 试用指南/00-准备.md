# 00 · 准备

🎯 **这一节验证什么：** 环境齐全，CLI 能跑起来。

前置：无。这是第一篇。各篇分别需要什么，见 [00b-底层环境清单](00b-底层环境清单.md)。

---

## ▶️ 操作

```bash
cd <仓库根目录>            # 例如 cd ~/Desktop/github/brickKit
./试用指南/准备.sh
```

脚本只做三件事，没有魔法：

1. `go build` 出 `试用指南/bin/brickkit`
2. 把 `tests/components/` 里的四个真实组件按 `<scope>/<name>` 布局拷进 `试用指南/playground/components/`
3. 如果没有独立的 `kubectl`，把 minikube 自带的那个链到 `试用指南/bin/`

然后按它最后一行的提示，把 `bin` 加进 PATH：

```bash
export PATH="$(pwd)/试用指南/bin:$PATH"
brickkit version
```

## ✅ 预期

```
BrickKit CLI 0.0.0-dev
支持的 Manifest 版本：brickkit/v1
支持的部署目标：docker、k8s
```

> **stderr 上那一串 JSON 是什么？** 是 CLI 的结构化日志，走 stderr，不影响正常输出。嫌吵就加 `--log-level off`，本指南后面的命令都可以加。

## 环境要求

| 工具 | 版本 | 哪几节需要 |
| --- | --- | --- |
| Go | 1.22+ | 编译 CLI |
| Docker | 20.10+ + Compose V2 | 01–06、08、09 |
| minikube | 任意 | 07 |

检查：

```bash
go version && docker version --format '{{.Server.Version}}' && minikube version --short
```

## 试验用的四个组件

它们是**真的组件**，不是占位符：能跑、有健康检查、有迁移、有依赖关系。源码在 [tests/components/](../tests/components/)。

| 组件 | 语言 | 依赖 | 特点 |
| --- | --- | --- | --- |
| `demo/hello` | Go | 无 | 最小组件，叶子节点 |
| `demo/caller` | Go | 强依赖 `demo/hello`<br>弱依赖 `demo/bus`（**故意不存在**）<br>资源：postgresql | 演示强/弱依赖与级联 |
| `department/tree` | Go | 资源：postgresql | 单端口双协议（HTTP + gRPC）、有迁移、有 artifacts |
| `people/basic` | Python | 强依赖 `department/tree`<br>弱依赖 `infra/redis-event-bus`（**故意不存在**）<br>资源：postgresql | `extraPorts`（gRPC 独立端口）、有迁移、有 configSchema |

镜像已经在本机构建好了（`brickkit-demo/*`）。确认一下：

```bash
docker images | grep brickkit-demo
```

看不到的话，逐个构建：

```bash
cd tests/components/demo-hello       && docker build -t brickkit-demo/hello:1.0.0 .
cd ../demo-caller                    && docker build -t brickkit-demo/caller:1.0.0 .
cd ../department-tree                && docker build -t brickkit-demo/department-tree:1.0.0 .
cd ../people-basic                   && docker build -t brickkit-demo/people-basic:1.0.0 .
```
