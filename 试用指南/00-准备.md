## ▶️ 操作

```bash
cd <仓库根目录>            # 例如 cd ~/Desktop/github/brickKit
./试用指南/准备.sh --images
```

`--images` 会顺带把十个组件的镜像全构建出来（第一次要几分钟）。
只想先看看 CLI、还不打算起容器的话，不加 `--images` 也行——但 05 之后每一篇都要它。

脚本做的事没有魔法：

1. `go build` 出 `试用指南/bin/brickkit`
2. 把 `tests/components/` 下的**十个**真实组件按 `<scope>/<name>` 布局拷进 `试用指南/playground/components/`
3. `--images` 时调 `make demo-images` 构建镜像
4. 如果没有独立的 `kubectl`，把 minikube 自带的那个链到 `试用指南/bin/`

然后按它最后一行的提示，把 `bin` 加进 PATH：

```bash
export PATH="$(pwd)/试用指南/bin:$PATH"
brickkit version
```

## 三个命名状态

**每一篇的前置都是一条命令，不是"前面 N 篇做完"。** 想从哪一篇开始就从哪一篇开始，
试花了就再跑一次——**reset 是常规手段，不是应急措施**。

| 命令 | 得到什么 | 哪几篇用它 |
| --- | --- | --- |
| `./试用指南/准备.sh --images` | 十个组件镜像 + `hello:2.0.0`（08 要用） | 05 之后的每一篇 |
| `./试用指南/准备.sh --reset` | 空试验场：只有十个组件的**源码**，没有项目 | 01、02 |
| `./试用指南/准备.sh --baseline` | **五组件基准**：`demo-shop` 项目已建好，五个组件已装 | 03 · 04 · 05 · 07 · 08 · 19 |

`--baseline` 隐含 `--reset`——基准状态的意义就在于每次都一样。它等价于：

```bash
./试用指南/准备.sh --reset
cd 试用指南/playground
brickkit init demo-shop
brickkit add demo/caller@1.0.0 -y     # 连带拉来 demo/hello
brickkit add people/basic@1.0.0 -y    # 连带拉来 department/tree 和弱依赖 infra/redis-event-bus
```

剩下几篇各有各的起点，都写在自己的前置里：13–16、18 用 13 自己建的 `erp-demo` 项目；
10–12 要市场后端；09 只要一个 minikube；17 从一个空目录开始写你自己的组件。

## 试验用的十个组件

它们是**真的组件**，不是占位符：能跑、有健康检查、有迁移、有依赖关系。源码在 [tests/components/](../tests/components/)。

**两个玩具**（起得快、看得清，01–08 用它们讲依赖与启停）：

| 组件 | 语言 | 依赖 | 特点 |
| --- | --- | --- | --- |
| `demo/hello` | Go | 无 | 最小组件，叶子节点 |
| `demo/caller` | Go | 强依赖 `demo/hello`<br>弱依赖 `demo/bus`（**故意不存在**）<br>资源：postgresql | 演示强/弱依赖与启停判定 |

**八个真实组件**（13 的完整装配用它们拼出一个能登录、能审批的系统）：

| 组件 | 语言 | 特点 |
| --- | --- | --- |
| `department/tree` | Go | 单端口双协议（HTTP + gRPC）、有迁移、有 artifacts |
| `people/basic` | Python | `extraPorts`（gRPC 独立端口）、有迁移、有 configSchema |
| `auth/password-login` | Go | 登录发令牌，有迁移与种子数据 |
| `authorization/rbac` | Go | Redis 当**加速器**（挂了回源查库） |
| `erp/backend` | Go | 连接组件，强依赖四个 + 弱依赖事件总线 |
| `portal/user-frontend` | nginx | 前端组件，`expose: true` 从浏览器访问 |
| `infra/redis-event-bus` | Go | Redis 当**数据源**（挂了就 503） |
| `infra/api-docs` | Go | 文档聚合，弱依赖所有人 |

### 镜像

`--images` 已经构建过了。确认一下：

```bash
docker images | grep brickkit-demo
```

应该有 **11 个**（十个组件 + `hello:2.0.0`——08 讲升级时要用它）。

漏了或想单独重建：

```bash
make demo-images        # 镜像名与标签的唯一事实源在 Makefile 里
```

> 早先这里手抄了四条 `docker build`，而试验场里有十个组件——照着做的人会在 08 与
> 13 撞上 `ImagePullBackOff`，且没有任何一篇告诉他缺的是什么。现在只指向
> `make demo-images` 一处，不再有第二份清单会过期。
