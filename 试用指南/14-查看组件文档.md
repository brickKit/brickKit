# 14 · 查看别人的组件有哪些 API

🎯 **这一节验证什么：** 你要调用一个别人写的组件，怎么知道它有哪些接口、
参数长什么样、怎么生成客户端代码。

前置：走完 [12-完整装配.md](12-完整装配.md)。

---

## 三条路，用途不同

| 路 | 什么时候用 | 需要组件在跑吗 |
| --- | --- | --- |
| **产物文件**（`.brickkit/artifacts/`） | **写代码时** —— 生成客户端、看字段定义 | ❌ 不需要 |
| **文档中心**（`infra/api-docs`） | **排障时** —— 这个接口现在到底长什么样 | ✅ 需要 |
| **gRPC Reflection**（`grpcurl`） | **手动试一发** —— 不写代码直接调 | ✅ 需要 |

第一条是主线：BrickKit 的原则是**契约即产物**（002 §7）——
组件把 `.proto` 和 `openapi.json` 作为产物发布，调用方 `add` 的时候就拿到了，
不需要读对方的源码，也不需要对方的服务在跑。

---

## 14.1 产物：`add` 的时候就到手了

### ▶️ 操作

```bash
cd 试用指南/erp-demo      # 12 节建的项目
find .brickkit/artifacts -type f | sort
```

### ✅ 预期

```
.brickkit/artifacts/authorization-rbac-1-0-0/api-contract/proto/authorization/v1/authorization.proto
.brickkit/artifacts/authorization-rbac-1-0-0/api-docs/openapi.json
.brickkit/artifacts/auth-password-login-1-0-0/api-docs/openapi.json
.brickkit/artifacts/department-tree-1-0-0/api-contract/proto/department/v1/department.proto
.brickkit/artifacts/department-tree-1-0-0/api-docs/openapi.json
.brickkit/artifacts/erp-backend-1-0-0/api-docs/openapi.json
.brickkit/artifacts/infra-redis-event-bus-1-0-0/api-docs/openapi.json
.brickkit/artifacts/people-basic-1-0-0/api-contract/proto/people/v1/people.proto
.brickkit/artifacts/people-basic-1-0-0/api-docs/openapi.json
```

目录结构是 `<版本化服务名>/<产物类型>/<文件路径>`。两种类型：

| 类型 | 是什么 |
| --- | --- |
| `api-contract` | gRPC 的 `.proto` —— **拿它生成客户端代码** |
| `api-docs` | `openapi.json` —— HTTP 接口的说明 |

### 看一眼契约

```bash
cat .brickkit/artifacts/people-basic-1-0-0/api-contract/proto/people/v1/people.proto
```

```protobuf
service PeopleService {
  rpc ListPeople(ListPeopleRequest) returns (ListPeopleResponse);
  rpc GetPerson(GetPersonRequest) returns (Person);
}

message Person {
  string id = 1;
  string name = 2;
  string department_id = 3;
  string department_name = 4;   // 由 people/basic 调 department/tree 补全
  string title = 5;
}
```

**这就是你要的全部信息。** 不用问对方要文档，不用读它的源码 ——
而且它是 Python 写的，源码对 Go 调用方也没什么用。

### ⏹️ 怎么停

只是读文件，没有需要停的东西。

## 14.2 用产物生成客户端代码

这是"契约即产物"真正的用处。`erp/backend` 就是这么做的。

### ▶️ 操作

```bash
mkdir -p /tmp/mycaller && cd /tmp/mycaller
cp -r <你的项目>/.brickkit/artifacts/people-basic-1-0-0/api-contract/proto .

# 用仓库里带的 protoc（试用指南/bin 已经在 PATH 里）
protoc --proto_path=proto \
  --go_out=gen --go_opt=paths=source_relative \
  --go-grpc_out=gen --go-grpc_opt=paths=source_relative \
  proto/people/v1/people.proto
```

### ✅ 预期

```
gen/people/v1/people.pb.go
gen/people/v1/people_grpc.pb.go
```

现在你有了一个 Go 客户端，可以直接调 `people/basic` —— 而它是 Python 组件。
这就是跨语言拼装的样子。

> **`go_package` 要自己加。** `people/basic` 的 `.proto` 里没有这一行 ——
> 它是 Python 组件，生成选项属于**调用方**，不该要求发布者为每种语言都预先写一遍。
> `erp/backend` 就是这么处理的，见
> [tests/components/erp-backend/proto/people/v1/people.proto](../tests/components/erp-backend/proto/people/v1/people.proto)。

### ⏹️ 怎么停

```bash
rm -rf /tmp/mycaller
```

## 14.3 文档中心：现在到底长什么样

产物是**发布时**的快照。想知道**此刻跑着的**服务有哪些方法，用文档中心。

### ▶️ 操作

12 节里已经装过它了。没装的话：

```bash
brickkit add infra/api-docs@1.0.0
```

然后在 `brickkit.yaml` 里打开它（**没有任何组件依赖它**，所以要自己声明）：

```yaml
  - id: infra/api-docs
    version: 1.0.0
    enabled: true          # ← 它是个入口，没人依赖它
    expose: true
    exposePort: 18081
```

```bash
brickkit up
```

打开 <http://localhost:18081>，或者：

```bash
curl -s http://localhost:18081/api/v1/sources | python3 -m json.tool
```

### ✅ 预期

```
auth/password-login      no-docs      组件在线，但既没有 /openapi.json，也没有开 gRPC Reflection
authorization/rbac       ok    grpc   authorization.v1.AuthorizationService: Check, ListPermissions
department/tree          ok    grpc   department.v1.DepartmentService: GetDepartment, GetSubtree, ListDepartments
erp/backend              no-docs      组件在线，但既没有 /openapi.json，也没有开 gRPC Reflection
infra/redis-event-bus    ok    openapi
people/basic             ok    openapi
```

### 四种状态，各自对应不同的动作

这是文档中心最要紧的设计 —— 页面空着的时候，你需要知道**接下来该做什么**：

| 状态 | 含义 | 该做什么 |
| --- | --- | --- |
| `ok` | 拿到文档了 | — |
| `absent` | 平台没注入地址 = 组件**没装** | 装上它 |
| `unreachable` | 地址在，但连不上 | 去看那个组件 |
| `no-docs` | 组件在线，两条路径都没有 | 让它提供 `/openapi.json` 或开 Reflection |

上面 `auth/password-login` 和 `erp/backend` 显示 `no-docs` —— 它们的 `openapi.json`
是作为**市场产物**分发的（14.1 里你已经拿到了），但没有在运行时暴露成一个端点。
这是当前的真实状态，不是 bug；要改的话得给这些组件加一个 `GET /openapi.json`。

### 试试把某个组件停掉

```bash
docker stop $(docker ps -qf name=department-tree)
sleep 32                       # 文档中心的探测结果缓存 30 秒
curl -s http://localhost:18081/api/v1/sources | grep -A2 department
```

状态会从 `ok` 变成 `unreachable`，而**其余组件的文档照常显示** ——
一个组件挂了不会让整个文档中心变成白页。

```bash
docker start $(docker ps -aqf name=department-tree)
```

### ⏹️ 怎么停

```bash
# 只关文档中心：把 enabled 改回 false，或
docker stop $(docker ps -qf name=infra-api-docs)
```

## 14.4 gRPC Reflection：不写代码直接调一发

排障时最快的路：不需要 `.proto`，不需要生成代码。

### ▶️ 操作

`department/tree` 没有 `expose: true`，所以先临时把端口开出来：

```bash
NET=$(docker inspect $(docker ps -qf name=erp-backend) \
  --format '{{range $k,$v := .NetworkSettings.Networks}}{{$k}}{{end}}')

# 列出它有哪些服务
docker run --rm --network "$NET" fullstorydev/grpcurl:latest \
  -plaintext department-tree-1-0-0:8080 list
```

本机装了 grpcurl 的话（`试用指南/bin/grpcurl`），也可以先把端口映射出来再调。

### ✅ 预期

```
department.v1.DepartmentService
grpc.reflection.v1.ServerReflection
grpc.reflection.v1alpha.ServerReflection
```

```bash
# 看某个服务有哪些方法
docker run --rm --network "$NET" fullstorydev/grpcurl:latest \
  -plaintext department-tree-1-0-0:8080 list department.v1.DepartmentService

# 直接调
docker run --rm --network "$NET" fullstorydev/grpcurl:latest \
  -plaintext -d '{}' department-tree-1-0-0:8080 \
  department.v1.DepartmentService/ListDepartments
```

**注意端口是 8080，和 HTTP 同一个。** `department/tree` 是 Go 组件，
HTTP 与 gRPC 共用一个端口（h2c + Content-Type 分流）。

`people/basic` 不一样 —— 它是 Python 组件，grpcio 不能与 HTTP 共用端口，
所以在 Manifest 里声明了 `extraPorts`，gRPC 在 **9090**：

```bash
docker run --rm --network "$NET" fullstorydev/grpcurl:latest \
  -plaintext people-basic-1-0-0:9090 list
```

平台据此额外注入 `PEOPLE_BASIC_GRPC_ENDPOINT`，调用方用的就是它。

### ⏹️ 怎么停

`grpcurl` 跑完就退出，没有残留。

## 该用哪一条

```
我要写调用代码
   → 14.1 / 14.2：产物文件。不需要对方在跑，版本也确定
我不知道这个接口现在有没有变
   → 14.3：文档中心。看的是此刻跑着的服务
我就想手动试一发
   → 14.4：grpcurl + Reflection。最快
```
