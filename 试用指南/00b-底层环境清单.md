## 基础三件

### Docker

几乎每篇都要。版本 20.10+，Compose 用 V2（2022 年之后的都是）。

```bash
docker version          # 有输出就行
docker compose version  # 注意是 compose 不是 compose-plugin
```

### minikube（只有 07 / 15 / 17 / 19 要）

```bash
minikube start
minikube status         # host / kubelet / apiserver 都是 Running
```

**kubectl 不用单独装。** 准备脚本会把 minikube 自带的那个链过来：

```bash
./试用指南/准备.sh      # 顺带处理 kubectl
```

> 17 篇例外：它要**能真正执行 NetworkPolicy 的 CNI**。minikube 默认的 bridge
> **不执行**策略——生成的规则会被静默忽略，你会以为收紧了其实没有。
> 那一篇开头有 `minikube start --cni=calico` 的独立集群命令。

### CLI 自己

```bash
./试用指南/准备.sh      # 编译出 试用指南/bin/brickkit
```

## 市场那条线（09 / 11 / 20）

市场比别的篇多好几层，这里一次说清。

### 它是四个容器，不是一个

```
market-api      市场本体（Go，8 MB 镜像）
postgres:15     元数据：组件、版本、用户、组织、访问策略、审计   150 MB
rustfs:latest   产物文件（S3 兼容对象存储）                      81 MB
rustfs-init     一次性容器，把数据目录属主改成 10001            2 MB
```

`rustfs-init` **跑完就退出**，`docker compose ps` 默认看不到它——用 `ps -a`。
少了它 RustFS 会以 `Permission denied (os error 13)` 反复重启。

### 起之前要有的三样

**① 市场镜像**（公开仓库没有，必须自己构建一次）

```bash
docker build -t brickkit/market-server:dev --build-arg VERSION=dev market-server/
```

不构建的话 `docker compose up -d` 会报：

```
pull access denied for brickkit/market-server, repository does not exist
```

**② `.env`，且必须和 compose 文件同目录**

```bash
cd deploy/market
cp .env.example .env
vi .env    # 至少填 POSTGRES_PASSWORD / RUSTFS_SECRET_KEY / ADMIN_PASSWORD
```

⚠️ **宿主机 shell 里 export 过的同名变量会盖掉 `.env`**，而且不报错——
服务照常 healthy，只是口令不是你配的那个。起完检查一下：

```bash
docker compose config | grep -E "POSTGRES_(USER|PASSWORD)"
```

对不上就 `unset` 掉宿主机那个同名变量再重来（改 `.env` 没用，优先级更低）。

**③ 空闲端口**

| 端口 | 谁用 | 冲突了改哪 |
| --- | --- | --- |
| 8080 | 市场 API | `.env` 的 `MARKET_PORT` |
| 9001 | RustFS 管理界面 | `.env` 的 `RUSTFS_CONSOLE_PORT` |

RustFS 的 S3 端口 9000 **不发布到宿主机**，不会冲突。
本机跑着别的 MinIO/RustFS 时最容易撞 9001：

```
Bind for 0.0.0.0:9001 failed: port is already allocated
```

### 起来之后

```bash
docker compose ps -a            # 四个：三个 Up + 一个 Exited (0)
curl http://localhost:8080/api/v1/health
```

### 停掉与清数据

```bash
docker compose down             # 停，数据保留在 deploy/market/data/
docker compose down -v          # 连 volume 一起删
```

**数据目录不能直接 `rm -rf`** —— 属主是容器内的用户：

```bash
docker run --rm -v "$PWD/data:/data" busybox rm -rf /data/postgres /data/rustfs
```

> ⚠️ **起过市场之后 `go test ./...` 会失败**，报
> `open deploy/market/data/postgres: permission denied`。
> `.gitignore` 里有这个目录，但 **Go 遍历不看 .gitignore**。
> 跟你的测试毫无关系——按上面那条命令清掉即可。

## cosign（只有 11 篇要）

```bash
go install github.com/sigstore/cosign/v2/cmd/cosign@latest
```

装到 `~/go/bin/cosign`（约 131 MB），不碰系统目录。确认：

```bash
~/go/bin/cosign version     # 或把 ~/go/bin 加进 PATH
```

### 谁需要装，谁不需要

这是签名设计里最要紧的一条：

| 角色 | 命令 | 要不要 cosign |
| --- | --- | --- |
| **发布者** | `brickkit publish --sign` | **要**。通常在 CI 里，一次性配好 |
| **使用者** | `brickkit add`（验签） | **不要**。Go 标准库直接验 |

`cosign sign-blob` 产出的就是标准 ECDSA P-256 签名（ASN.1 DER + base64），
公钥是 PKIX PEM，标准库本来就能验。

**为什么值得这么设计：** 如果验签也要装 cosign，那"生产环境强制签名"就意味着
每台机器、每个 CI runner 都得装它——大多数团队会因此直接把校验关掉，
安全措施变成摆设。

> 这条互操作性不是推断出来的：`internal/security/cosign_interop_test.go` 用
> **真 cosign** 双向验过（cosign 签 → 标准库验、我们的规范化输出 → cosign 验）。
> 没装 cosign 时那组测试会自动跳过，装了就自动跑（它会去 `~/go/bin` 找）。

## 组件镜像（05 之后基本都要）

```bash
./试用指南/准备.sh          # 会列出要构建哪些
```

或者手动（00-准备 里有完整列表）：

```bash
cd tests/components/demo-hello && docker build -t brickkit-demo/hello:1.0.0 .
# ……其余同理
```

K8s 篇（07 / 15 / 19）还要**把镜像装进集群**：

```bash
minikube image load brickkit-demo/hello:1.0.0
```

不装的话 Pod 会一直 `ImagePullBackOff`——集群里的 Docker 和你本机的不是同一个。
