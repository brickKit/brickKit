# 07 · 本地调试（`local: true`）

🎯 **这一节验证什么：** 让一个组件在你的 IDE 里跑（能打断点），其余组件照常在容器里，两个方向都能互通。

前置：05 做完，四个组件跑得起来。

---

## 7.1 问题是什么

你想调 `people/basic` 的代码，但它依赖 `department/tree`，还要连数据库。传统做法是本地把整套依赖都装一遍。

BrickKit 的做法：**只把这一个组件从容器里拿出来**，其余不动。两个方向的连通都由 CLI 打通：

| 方向 | 问题 | CLI 的做法 |
| --- | --- | --- |
| 容器 → 你的进程 | 容器里 `people-basic-1-0-0` 这个名字解析不到宿主机 | 给依赖方加 `extra_hosts`，把服务名指向 `host-gateway` |
| 你的进程 → 容器 | 你的机器上 `department-tree-1-0-0` 这个名字不存在 | 把依赖与资源的端口映射到宿主机，并生成一份 `.env` 指向 `localhost` |

---

## 7.2 打开本地调试

### ▶️ 操作

```yaml
  - id: people/basic
    version: 1.0.0
    local: true          # ← 加这一行
    # localPort: 8080    # 可选；不写就用组件自己声明的 deployment.port
```

```bash
brickkit up
```

### ✅ 预期

`people/basic` **不再出现在启动列表里**（3 个组件而不是 4 个），末尾多一行提示：

```
✅ 全部组件已启动（3 个）

💡 查看状态：brickkit status
   本地调试：在 IDE 中加载 .brickkit/generated/local-debug.people-basic-1-0-0.env 启动 people/basic
```

它的**迁移也不会跑**（迁移容器跟着组件一起没了）——CLI 会警告一句，你得自己在 IDE 里跑迁移。

---

## 7.3 看那份 env 文件

### ▶️ 操作

```bash
cat .brickkit/generated/local-debug.people-basic-1-0-0.env
```

### ✅ 预期

```bash
# 组件：people/basic@1.0.0（local: true）
# 本地监听端口：8080 —— 请让 IDE 里启动的进程监听这个端口
# 用法：VS Code 在 launch.json 里配 envFile；
#       命令行 `set -a && source 本文件 && set +a` 之后再启动进程

COMPONENT_ID=people/basic
COMPONENT_VERSION=1.0.0
DATABASE_HOST=localhost
DATABASE_NAME=people
DATABASE_PASSWORD=devpass          ← 真值，不是 ${PG_PASSWORD}
DATABASE_PORT=15432                ← 容器里的 5432 映射到宿主机的 15432
DATABASE_USER=brickkit
DEPARTMENT_TREE_ENDPOINT=http://localhost:18080   ← 依赖被映射到宿主机
LOG_LEVEL=info
```

三处关键：

1. **地址全部改成 `localhost:<映射端口>`** —— 你的进程不在容器网络里，用服务名连不上。
2. **端口按 `10000 + 容器端口` 分配**（5432 → 15432，8080 → 18080），被占了就往后找。
3. **`${VAR}` 已经求好值** —— 这个文件是给 IDE 读的，VS Code 的 `envFile` 与 IntelliJ 的 EnvFile 插件**都不做变量替换**，留占位符的话你的进程会拿着字面量 `${PG_PASSWORD}` 去连库。

> 对比一下：`docker-compose.yaml` 里**故意**保留 `${PG_PASSWORD}`——那份文件会被人打开看、进 git diff，明文密码进去就等于泄露，而 docker compose 自己会从 `.env` 展开。**谁不做替换，就在生成时替换给谁。**

文件权限是 `0600`，`.brickkit/generated/` 也在 `.gitignore` 里。

## 7.4 真的跑起来

### VS Code

`.vscode/launch.json`：

```jsonc
{
  "configurations": [{
    "name": "people/basic",
    "type": "debugpy",
    "request": "launch",
    "module": "app.main",
    "cwd": "${workspaceFolder}/components/people/basic",
    "envFile": "${workspaceFolder}/.brickkit/generated/local-debug.people-basic-1-0-0.env"
  }]
}
```

### 命令行

```bash
cd components/people/basic
set -a && source ../../../.brickkit/generated/local-debug.people-basic-1-0-0.env && set +a
python -m app.main migrate      # 迁移得自己跑（容器里那个没了）
python -m app.main              # 启动，监听 8080
```

### 验证两个方向

```bash
# 你的进程 → 容器里的依赖
curl http://localhost:18080/healthz          # department/tree

# 容器里的组件 → 你的进程（从任意一个容器里发起）
docker exec brickkit-demo-shop-demo-hello-1-0-0-1 \
  wget -qO- http://people-basic-1-0-0:8080/healthz
```

第二条能通，靠的就是 `extra_hosts` 把 `people-basic-1-0-0` 指向了宿主机。

## 7.5 多个组件同时调

给几个组件都加 `local: true` 即可，CLI 为**每一个**生成独立的 env 文件（按版本化服务名命名），端口自动错开。

---

## ⏹️ 怎么停

| 停什么 | 怎么停 |
| --- | --- |
| IDE 里那个进程 | 停止调试 / `Ctrl-C` |
| 其余容器 | `brickkit down` |
| 回到"全部跑容器" | 删掉 `local: true` 那一行，再 `brickkit up` |

删掉 `local: true` 之后 `up` 会把 `people/basic` 重新拉回容器里，端口映射与 `extra_hosts` 一并消失。
