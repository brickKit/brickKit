# 20 · 市场进阶：账号、可见性、组织、审计

> **这一篇解决什么：** [09](09-组件市场.md) 讲的是"发出去、装回来"。
> 这一篇讲**发出去之后**的事：谁能看见、谁能装、谁改过什么。
>
> **前置：** [09](09-组件市场.md)（市场已经起来、admin 已登录、demo/hello 已发布）。
>
> 本篇全程用 `curl`——这些是**市场的能力**，CLI 目前只包了登录、发布、安装三条。
> 其余用 HTTP 直接调，也方便你接进自己的运维脚本。

## 先拿一个 token

下面每条命令都要它：

```bash
B=http://localhost:8080/api/v1
TOK=$(curl -s -X POST $B/auth/login -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"<你的 ADMIN_PASSWORD>"}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")
A="Authorization: Bearer $TOK"
```

> token 是**存库的不透明随机串**（64 位），不是 JWT。
> 所以"登出"和"重置口令"能让旧 token 立刻失效——自包含的 JWT 在过期前吊销不掉。

## 20.1 注册普通用户

admin 是引导账号。真实使用里每个人有自己的账号：

```bash
curl -s -X POST $B/auth/register -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"AlicePass123","email":"alice@example.com"}'
```

### ✅ 预期

```json
{"success":true,"data":{"userId":"user-770e182a0029d88407c629eed2f938ee",
 "username":"alice","email":"alice@example.com","createdAt":"..."}}
```

**注册接口不接受 `orgId`。** 这是补过的一个越权漏洞：早先版本允许注册时自报组织，
于是任何人自报 `orgId` 就能读走该组织全部 private 组件。现在组织成员只能由
组织所有者添加（20.3）。

---

## 20.2 谁能看见：public 与 private

刚发布的组件是 `public`——匿名就能查、能装。改成私有：

```bash
curl -s -X PUT $B/components/demo/hello/visibility -H "$A" \
  -H "Content-Type: application/json" -d '{"visibility":"private"}'
```

```json
{"success":true,"data":{"componentId":"demo/hello","visibility":"private"}}
```

### 验证：匿名现在拿不到

```bash
curl -s $B/components/demo/hello/versions/1.0.0/manifest
```

```json
{"success":false,"error":{"code":"FORBIDDEN","message":"无权访问该组件：demo/hello",
 "details":{"componentId":"demo/hello","visibility":"private"}}}
```

**注意错误码是 `FORBIDDEN` 而不是 `NOT_FOUND`。** 这是有意的：
对**已认证但无权**的人说"你没权限"，比假装组件不存在更有用——
后者会让人以为是自己版本号写错了，去查一个根本不存在的问题。

## 20.3 组织：把权限给一群人，而不是一个个给

```bash
# 建组织（orgId 由服务端生成，你传的会被忽略）
curl -s -X POST $B/organizations -H "$A" \
  -H "Content-Type: application/json" -d '{"name":"ACME 公司"}'

# 取回真实 orgId
OID=$(curl -s $B/organizations -H "$A" \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['organizations'][0]['orgId'])")
echo $OID     # org-3ada361411941ebf839f0644b4613ad6

# 加成员
curl -s -X POST $B/organizations/$OID/members -H "$A" \
  -H "Content-Type: application/json" -d '{"username":"alice","role":"member"}'
```

### ✅ 预期

```json
{"success":true,"data":{"orgId":"org-3ada...","status":"added","username":"alice"}}
```

> **`orgId` 由服务端生成，不是你起的名字。** 上面第一条命令里就算写了
> `"orgId":"acme"` 也会被忽略——组织标识不能由客户端指定，
> 否则两个人可以抢同一个 ID。

## 20.4 访问策略：把 private 组件授权出去

private 之后，除了所有者谁都装不了。授权给刚建的组织：

```bash
curl -s -X PUT $B/components/demo/hello/access -H "$A" \
  -H "Content-Type: application/json" \
  -d "{\"policies\":[{\"targetType\":\"organization\",\"targetId\":\"$OID\",\"permission\":\"read\"}]}"
```

```json
{"success":true,"data":{"componentId":"demo/hello","policies":1}}
```

`targetType` 可以是 `organization` 或 `user`——授权给一个人也行，
但**组织是可维护的那个**：人来人往时改成员表，不用回来翻每个组件的策略。

> ⚠️ **这是全量替换，不是追加。** 传进去的 `policies` 数组就是最终状态，
> 传空数组等于**收回全部授权**。要加一条时先 `GET` 回来再追加。

## 20.5 审计：谁改过什么

```bash
curl -s $B/audit -H "$A" | python3 -m json.tool | head -20
```

### ✅ 预期

```
共 21 条：
   user.login
   component.access_changed      demo/hello     admin
   component.visibility_changed  demo/hello     admin
   user.login                                   admin
```

上面每一步操作都留了痕：改可见性、改访问策略、登录。

**这一条是给"半年后"用的。** 某个组件突然装不上了，问谁改的——
`component.visibility_changed` 会告诉你是谁、什么时候把它改成了 private。

## 20.6 版本状态：为什么发布是三步

`brickkit publish` 一条命令背后是三步：

```
建 draft  →  上传每个产物文件  →  转 stable
```

看现在的状态：

```bash
curl -s $B/components/demo/hello/versions/1.0.0/manifest \
  -H "$A" | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['status'])"
```

```
stable
```

**为什么要 draft 这个中间态：** 发布请求里只有元数据，文件还没上传；
而"上传的文件必须与 `files` 列表一致"这条规则得等文件到齐才能判。
所以 draft 是"已登记、待上传"，转 stable 时统一校验——
**少传一个文件就转不成 stable，别人装不到半成品组件**。

`blocked` 是第三种状态（下架）。装一个 blocked 版本会得到
`COMPONENT_BLOCKED` 而不是笼统的认证失败——两者该做的下一步完全不同。

## 20.7 登出

```bash
curl -s -X POST $B/auth/logout -H "$A"
```

之后拿旧 token 调任何接口都会被拒。CLI 侧删掉 `.brickkit/credentials` 即可。

## ⏹️ 怎么停

```bash
cd deploy/market && docker compose down
```

数据在 `deploy/market/data/`，`down` 不会删。要彻底清空：

```bash
docker compose down -v
docker run --rm -v "$PWD/data:/data" busybox rm -rf /data/postgres /data/rustfs
```

> 宿主机直接 `rm -rf data/` 会提示没权限——那些目录属主是容器内的用户（uid 10001）。

## 一句话总结

```
public          谁都能看能装
private         只有所有者 + 被 access 授权的人
组织            把授权给一群人，人员变动时只改成员表
审计            半年后回答"这是谁改的"
draft→stable    保证别人装不到半成品
```
