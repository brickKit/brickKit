# BrickKit 文档

文件夹和文件名前面的**编号，就是推荐的阅读顺序**：从 00 往后读，前面的是后面的基础。不想从头读的话，看下面的"三条路线"。

## 按编号顺序

| 编号 | 读什么 | 读完你会 | 什么时候读 |
| --- | --- | --- | --- |
| 00 | [Quick Start](00-quick-start.md) | 用 5 分钟把一个组件跑起来，并用 HTTP 访问到它 | 第一次接触，先动手 |
| 01 | [核心概念](01-concepts.md) | 认得文档和报错里的术语，记住那条贯穿一切的命名规则 | 跑起来之后，想弄懂刚才发生了什么 |
| 02 | [和现有方案对比](02-comparison.md) | 知道它和 Docker Compose、Helm 等各自解决什么，什么时候该选谁 | 还在评估要不要用 |

## 三条路线

- **第一次用：** 00 → 01 → 03（先读前几篇教程）
- **要自己开发组件：** 03 里的第 12 篇 → 04 → 05 → 07 里的 00–04
- **要部署到生产：** 06 里的 00–03 → 07 里的 05–09 → 08
- **只想查某个命令怎么用：** [命令一览](06-architecture/09-cli-reference.md#命令一览)——每个命令一句话加"什么时候用"，点进去是完整的参数和真实输出
