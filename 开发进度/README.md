## 状态图例

| 图例 | 含义 |
| --- | --- |
| ⬜ | 未开始 |
| 🚧 | 进行中 |
| ✅ | 已完成并通过该 Step 的全部测试验证项，且**没有**留给后续 Step 的回填项 |
| ⚠️ | 已通过该 Step 的全部测试验证项，但**有意延后**了部分内容（见"延后实现清单"，逐条列明回填 Step） |

⚠️ 不是"没做完"，而是"当前阶段做不完整、硬做只会做出半成品"——依赖后续 Step 才具备的信息。
每条延后项都在下面的《延后实现清单》里有编号、原因与回填 Step，**不看清单只看总览表会误以为该 Step 全做完了**。

## 使用约定

1. 每个窗口开始时：读取本文件，先看《延后实现清单》里"回填 Step"等于本窗口 Step 的条目，
   再找到第一个 ⬜ / 🚧 的 Step，两者合并为本窗口目标。
2. 每个窗口结束时：更新总览表状态 + 追加"完成记录"小节（含验证结果与产出文件）；
   本窗口回填掉的清单条目标记为 ✅ 并写明落地位置；本窗口新增的延后项追加到清单末尾。
3. Commit 建议：每个 ✅ / ⚠️ 的 Step 可作为一次独立 commit，建议信息格式
   `Step <N>: <Step 名称>`。
4. `市场部署与运维指南.md` 对应的部署/运维工作放在最后（Step 40 之后）执行，前期不涉及。
