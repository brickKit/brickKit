# Generating a skeleton

## `brickkit new`

```bash
brickkit new demo/quote --path demo-quote --contract openapi
```

```text
✅ Component skeleton generated: demo/quote
   📄 demo-quote/component.yaml
   📄 demo-quote/BRICKKIT.md
   📄 demo-quote/AGENTS.md
   📄 demo-quote/CLAUDE.md
   📄 demo-quote/README.md
   📄 demo-quote/api/openapi.yaml

Next steps:
  Fill in the TODOs in component.yaml and the docs (brickkit lint lists every one left)
  cd demo-quote && brickkit init    give it a local workbench (completion mode: existing files are left alone)
  brickkit lint                     check component.yaml and the docs
```

| Written | Goes to | When |
| --- | --- | --- |
| `brickkit new demo/quote` | The project's `components/demo/quote/` | Writing a new component inside a project; local install sources scan exactly this layout, so `brickkit add --local` brings it in when you're done |
| `brickkit new demo/quote --path demo-quote` | `demo-quote/`, without the `<scope>/<name>` layer | A component in a repository of its own (recommended: one component per repository) |
| `brickkit new erp/shell --shell` | The project's `shell/erp/shell/` | A shell: its `component.yaml` carries a placeholder member to replace |

`--contract openapi` or `--contract proto` also generates a contract placeholder and registers it under `artifacts`.

## What it generates

**`component.yaml`**: a skeleton that already passes validation, with `TODO` wherever something has to change:

```yaml
# demo/quote — skeleton generated by brickkit new
# Every TODO below has to be replaced with the real thing; the structure itself already passes brickkit up --dry-run validation
apiVersion: brickkit/v1
kind: Component

metadata:
  id: demo/quote
  name: quote # TODO: change to a human-readable display name
  version: 0.1.0
  description: TODO — say in one sentence what this component does

artifacts:
  - type: api-contract
    format: openapi
    files:
      - api/openapi.yaml

deployment:
  type: container
  build: # built locally with brickkit build (up never builds); add image: <registry>/<name> once you publish a prebuilt image
    context: .
    dockerfile: Dockerfile
  port: 8080 # TODO: replace with the port the component actually listens on

healthCheck:
  type: http
  path: /healthz
  # If the cold start takes longer than the default 60 seconds (a heavy Spring Boot / Django preload / .NET first JIT, etc.),
  # set startPeriodSeconds, or it will CrashLoopBackOff permanently under K8s
```

**Four documents**, each section holding a `<!-- TODO: … -->` hint that says what goes there (`brickkit lint` lists every
hint still left):

| File | For | What the skeleton holds |
| --- | --- | --- |
| `BRICKKIT.md` | The people and AIs using the component | Six sections: Purpose, Before you deploy, Dependencies, Configuration, Contracts, Shell declaration; the contract file is already listed under Contracts |
| `AGENTS.md` | The AI developing the component | Five sections: Code map, Build and test, Design decisions, Pitfalls, Before changing code; then the block the CLI maintains, with the component rules |
| `CLAUDE.md` | Claude Code | One line: `@AGENTS.md` |
| `README.md` | People on GitHub | Use it in a project (the `add` command with this version), Documentation (a table linking the other files), Development |

What goes in each one: [A component's documentation](08-component-doc-spec.md).

**A contract placeholder**: `api/openapi.yaml`, an empty OpenAPI document.

**What it doesn't generate**: a Dockerfile, source, `go.mod` and the like. The platform doesn't pick a language or
framework for you; nor does it `add` the result to any project — writing into `brickkit.yaml` is a separate step you can
review.

## From skeleton to a component that runs

`demo/quote` returns a quotation each time, prefixed with `demo/hello`'s greeting.

**1. Fill in `component.yaml`.** Write the name, description, dependencies and config items:

```yaml
metadata:
  id: demo/quote
  name: Quote
  version: 0.1.0
  description: Returns a quotation each time, prefixed with demo/hello's greeting

dependencies:
  components:
    - demo/hello@1.1.0

configSchema:
  type: object
  properties:
    QUOTE_PREFIX:
      type: string
      default: "Quote of the day: "
      description: The prefix put in front of the quotation
```

**2. Write the code.** Dependency addresses and the component's own config are both read from environment variables:

```go
// demo/quote: returns a quotation each time, prefixed with demo/hello's greeting.
package main

import (
	"encoding/json"
	"log"
	"math/rand"
	"net/http"
	"os"
)

var quotes = []string{"Simple is better than complex", "Explicit is better than implicit", "Working beats perfect"}

func main() {
	hello := os.Getenv("DEMO_HELLO_ENDPOINT") // the dependency address the platform injects
	http.HandleFunc("/healthz", func(w http.ResponseWriter, _ *http.Request) { w.Write([]byte("ok")) })
	http.HandleFunc("/api/v1/quote", func(w http.ResponseWriter, _ *http.Request) {
		greeting := "(demo/hello unreachable)"
		if resp, err := http.Get(hello + "/api/v1/hello"); err == nil {
			var body struct{ Greeting string }
			_ = json.NewDecoder(resp.Body).Decode(&body)
			resp.Body.Close()
			greeting = body.Greeting
		}
		json.NewEncoder(w).Encode(map[string]string{
			"greeting": greeting,
			"quote":    os.Getenv("QUOTE_PREFIX") + quotes[rand.Intn(len(quotes))],
		})
	})
	log.Println("demo/quote listening on :8080")
	log.Fatal(http.ListenAndServe(":8080", nil))
}
```

A few things worth copying:

- The dependency's address (`DEMO_HELLO_ENDPOINT`) is injected by the platform; the code hard-codes no address — the same
  code runs on Docker and on Kubernetes.
- When the dependency is unreachable for a while, the component keeps serving, with part of the content missing: how to
  degrade is the component's own business.
- `/healthz` only says this process is alive; it doesn't probe `demo/hello`.

**3. Write the Dockerfile.**

```dockerfile
FROM golang:1.22-alpine AS build
WORKDIR /src
COPY go.mod *.go ./
RUN CGO_ENABLED=0 go build -o /out/quote .

FROM alpine:3.20
RUN adduser -D -u 10001 app
COPY --from=build /out/quote /app/quote
USER 10001
ENTRYPOINT ["/app/quote"]
```

The image needs `wget` or `curl` (Docker's HTTP health check uses them; Alpine ships `wget`), and shouldn't run as root.

**4. Fill in the documents and the contract**: `BRICKKIT.md` for the users, `AGENTS.md` for whoever develops it next,
the first line of `README.md`; see [A component's documentation](08-component-doc-spec.md) and
[Contracts and artifacts](06-artifacts-and-contracts.md).

**5. Check it.**

```bash
cd demo-quote
brickkit lint
```

```text
📦 Component repository (has component.yaml, no brickkit.yaml): component.yaml and the component's docs are checked
✅ component.yaml
✅ ./ (docs)

📋 Checked 2 files: 0 with errors, 0 warnings
```

**6. Run it.** Build a local workbench in the component repository and run it together with its dependencies; see
[Developing inside a component](05-local-dev-fractal.md).

**7. Release it.** See [Releasing](07-release-workflow.md).
